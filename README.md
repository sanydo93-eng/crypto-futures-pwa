# crypto-futures-pwa

Зональный трейдинг по фьючерсам KuCoin: бот ищет ретесты FVG-зон, публикует
сигналы в Telegram с графиком и разбором «почему», ведёт каждую сделку до
выхода (максимум сутки) и считает статистику. Плюс PWA-приложение в стиле
Threads, где всё это видно на графике.

Ключи биржи **не нужны** — используются только публичные эндпоинты KuCoin.

## Быстрый старт на сервере

```bash
git clone https://github.com/sanydo93-eng/crypto-futures-pwa.git
cd crypto-futures-pwa
git checkout claude/server-tg-signals-setup-mxo0y9

./deploy.sh          # создаст .env из шаблона и остановится
nano .env            # вписать TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
./deploy.sh          # собрать и запустить

docker compose logs -f
```

Приложение поднимется на `http://<ip-сервера>:8080`. Обновления — `git pull && ./deploy.sh`.

При старте бот проверяет себя и падает с внятной ошибкой, если что-то не так:
неверный токен Telegram, несуществующий символ, неподдерживаемый таймфрейм,
неожиданный формат свечей.

## Telegram

1. Создать бота у [@BotFather](https://t.me/BotFather) → получить токен.
2. Добавить бота в канал **администратором** с правом «Публикация сообщений».
3. `TELEGRAM_CHAT_ID` — `@имя_канала` для публичного канала либо числовой id
   вида `-1001234567890` для приватного.

Токен живёт только в `.env` на сервере (права `600`, в git не попадает).
В репозитории секретов нет.

## Стратегия: ретест FVG

**Fair Value Gap (имбаланс)** — три свечи, где цена ушла так быстро, что первая
и третья не перекрываются:

```
бычий:  low[3] > high[1]   →  зона [high[1], low[3]]
медвежий: high[3] < low[1] →  зона [high[3], low[1]]
```

Логика входа:

1. Цена оставила за собой имбаланс — зону, которую проскочила.
2. Цена вернулась в зону и **отреагировала**: зашла внутрь и закрылась обратно
   за её границей. Закрытие внутри зоны или прошив насквозь — не сигнал.
3. Вход по закрытию свечи реакции, стоп — за границей зоны плюс буфер по ATR
   (если цена закрылась за зоной, идея мертва), цели — кратные риску.

Каждая зона живёт своей жизнью: `свежая → касания → сломана`. Нетронутая зона
ценится намного выше уже отработанной, сломанная не торгуется вовсе.

### Сила сигнала

Каждый сигнал получает оценку 0–100, собранную из семи факторов. У каждого
фактора есть человекочитаемое пояснение — оно и попадает в «почему» в Telegram
и в приложении. Число без объяснения хуже, чем отсутствие числа.

| Фактор | Вес | Что оценивает |
|--------|-----|---------------|
| Тренд | 25 | согласованность с EMA50/EMA200 |
| Свежесть зоны | 20 | сколько раз зону уже касались |
| Импульс | 20 | размер свечи, создавшей зону, в ATR |
| Геометрия зоны | 15 | не слишком узкая и не слишком широкая |
| Реакция | 10 | доля хвоста отбоя в диапазоне свечи |
| Объём | 10 | тихий откат в зону лучше шумного |
| RSI | 10 | штраф за вход в перегретое движение |

Класс: **A** ≥ 80, **B** ≥ 68, **C** ≥ 55, **D** ниже. Публикуются только
сигналы силой не ниже `STRAT_MIN_STRENGTH` (по умолчанию 55).

## Ведение сделки

Каждый сигнал открывает отслеживаемую сделку. На каждом цикле бот проигрывает
появившиеся свечи и решает: цель, стоп или время.

- **Потолок жизни сделки — сутки** (`MAX_HOLD_HOURS`, максимум 24). Отсчёт идёт
  от свечи входа, а не от момента записи в базу. По истечении — выход по рынку.
- После первой цели стоп переносится в безубыток (`MOVE_STOP_TO_BREAKEVEN`).
- Если одна свеча задела и стоп, и цель — **засчитывается стоп**. Порядок
  внутри свечи неизвестен, и честное допущение здесь то, которое хуже для
  статистики; иначе она польстит сама себе.
- Закрытие сделки уходит отдельным сообщением в канал с результатом в R.

## Статистика

Результат считается в **R** — прибыль в долях риска, поэтому сделки с разной
дистанцией стопа сравнимы между собой. В приложении: винрейт, сумма и средний R,
профит-фактор, среднее время в сделке, кривая доходности и разбивки по парам,
направлению, силе сигнала и классу.

## Приложение (PWA)

Тёмная лента карточек, устанавливается на телефон как обычное приложение
(«Добавить на экран „Домой“»), работает офлайн-оболочка.

- **Лента** — карточки сигналов: пара, направление, шкала силы, график с
  затенённой FVG-зоной и линиями входа/стопа/целей, плитки уровней,
  раскрывающийся блок «Почему такой сигнал» с разбором по факторам, и статус:
  сколько осталось до закрытия или с каким результатом закрылась.
- **Статистика** — сводка, кривая доходности и разбивки.
- Фильтр по парам, автообновление раз в минуту.

Графики рисуются на клиенте из тех же данных, что лежат в базе — снимок свечей
сохраняется вместе с сигналом, поэтому график можно перерисовать в любой момент
без обращения к бирже.

### API

| Метод | Назначение |
|-------|------------|
| `GET /api/feed?limit=&offset=&symbol=` | лента сигналов со статусом сделки |
| `GET /api/signals/{id}` | сигнал целиком, с полным снимком свечей |
| `GET /api/stats` | агрегированная статистика |
| `GET /api/config` | текущие настройки бота |
| `GET /api/health` | проверка живости (её же использует healthcheck) |

Приложение отдаётся публично, без авторизации. Если сервер смотрит в интернет и
это нежелательно — закрой порт файрволом либо поставь перед ним reverse-proxy
с basic-auth и HTTPS, а в `APP_URL` пропиши внешний адрес: он уходит ссылкой в
сообщения Telegram.

## Как это работает

```
KuCoin Futures API ──► closed_klines ──► FVG-зоны + скоринг ──► SQLite ──► Telegram (график)
   (публичный)         (без текущей                              │            + PWA
                        незакрытой свечи)                        ▼
                                                        TradeTracker: цель / стоп / сутки
```

- Бот просыпается по закрытию свечи (`CANDLE_LAG_SECONDS` — пауза, чтобы биржа
  успела отдать финальные данные).
- Незакрытая свеча всегда отбрасывается — сигналы не «перерисовываются».
- Один и тот же сигнал не уйдёт дважды даже после перезапуска; повтор в ту же
  сторону ждёт `COOLDOWN_CANDLES`, разворот отправляется сразу.
- Ошибка по одной паре не роняет цикл, ошибка рендера графика не блокирует
  сигнал — он уйдёт текстом.
- Сеть: ретраи с экспоненциальной задержкой, у Telegram отдельно обрабатывается
  `429 retry_after`.

### Порядок колонок в свечах

`/api/v1/kline/query` отдаёт голые массивы без имён полей, а порядок колонок у
спота и фьючерсов KuCoin отличается. Вместо того чтобы зашивать один вариант,
клиент определяет раскладку по самим данным (`high` обязан быть не ниже
`open`/`close`, `low` — не выше) и кэширует результат. Если ни одна раскладка не
сходится — бот падает с ошибкой, а не торгует по мусору.

## Своя стратегия

Логика подключается отдельным модулем, остальной код трогать не нужно:

```python
# bot/strategies/my_setup.py
from ..models import Candle, Side, Signal
from .base import Strategy, register

@register("my_setup")
class MySetup(Strategy):
    warmup = 120                      # сколько свечей нужно для расчёта

    def evaluate(self, symbol: str, candles: list[Candle]) -> Signal | None:
        ...                           # candles — закрытые, от старых к новым
        return Signal(symbol=symbol, side=Side.LONG, strategy=self.name,
                      candle_ts=candles[-1].ts, price=candles[-1].close,
                      stop_loss=..., take_profits=[...],
                      strength=..., grade=..., factors=[...],
                      reasons=["почему"])
```

Импортировать модуль в `bot/strategies/__init__.py`, поставить
`STRATEGY=my_setup` в `.env`. Любая переменная `STRAT_*` приезжает в стратегию
как параметр (`self.param_float("MY_PARAM", 1.5)`) — цифры крутятся без
пересборки образа.

Стратегия обязана быть stateless: дедуп, кулдаун, ведение сделки и отправка —
забота раннера.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest
.venv/bin/python -m pytest tests -q
```

68 тестов: индикаторы, обе раскладки свечей KuCoin, детекция FVG и жизненный
цикл зон, поведение стратегии, ведение сделки (цели, стоп, безубыток, таймаут,
ничья внутри свечи), хранилище, статистика и HTTP-эндпоинты.

`DRY_RUN=true` — считать сигналы и писать их в лог, ничего не отправляя в канал.

## Дисклеймер

Сигналы носят информационный характер и не являются инвестиционной
рекомендацией. Торговля фьючерсами с плечом сопряжена с риском потери всех
средств. Статистика прошлых сигналов не гарантирует будущий результат.
